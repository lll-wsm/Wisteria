# 代码块输入括号后内容被清空 —— 根因分析与修复方案

- 状态：已修复
- 日期：2026-08-31
- 涉及文件：`muya-core/src/muya/lib/contentState/inputCtrl.js`

## 1. 问题描述

在**不带语言标签的代码块**（``` 后直接换行、无 `js`/`py` 等语言名）内编辑时，输入 `(`、`[`、`{` 等自动配对字符后，**代码块里已输入的内容被清空**。

典型复现（真实 Electron 键盘事件流）：

| 输入序列 | 修复前表现 |
|---|---|
| 空代码块输入 `ab` | `ab` 正常显示 |
| 再输入 `(` | **整个内容消失，变空** |
| 再输入 `c` | 只有 `c` 显示（`ab()` 永久丢失） |

带语言标签的代码块（```js 等）完全正常。用户反馈"之前修复过很多轮都没有修好"。

## 2. 排查过程（证据链）

排查严格采用"打日志测原因、不猜测"的方式，在真实应用中逐层定位：

### 2.1 确定触发条件

多场景矩阵测试（空代码块 / 带语言代码块 / 行首 / 行尾 / 快速连打 / 中文括号）显示：

| 场景 | 现象 |
|---|---|
| 空代码块（无语言）+ 已有内容 + 输入 `(` | **内容清空**（`ab` → `""`） |
| 带语言代码块 + 输入 `(` | 正常自动补全 `()` |
| 行首输入 `(` | 正常（`(` 前有字符时不配对） |
| 快速连打 `(abc` | 正常 |

问题仅在**无语言代码块**中出现。

### 2.2 DOM 追踪：pre 被整体替换且重建内容为空

MutationObserver + 节点身份对比证明：

- 输入 `(` 后，`pre` 元素被**整体移除重建**（`sameNode: false`）
- 被移除的旧 `pre` 里内容是 `"ab("`（浏览器已插入的字符），**重建出的新 `pre` 是空的**
- 变更序列符合 muya 渲染器 `insertAdjacentHTML + remove` 的重建模式

说明：清空不是浏览器行为，而是 **muya 渲染逻辑重绘了代码块，但渲染输出为空**。

### 2.3 模型层验证：模型数据从未丢失

把 muya 实例句柄临时挂到 `window` 后直接读内存模型：

```
修复前输入 ( 后模型状态：
pre(fencecode) > languageInput("") + code(ag-96, text="ab()")  ← 模型完全正确
```

**内存模型里 `code` block 的 text 已经是正确的 `"ab()"`**（autoPair 补全生效），但 DOM 渲染为空。清空不是"数据丢失"，而是"渲染读错了对象"。

### 2.4 光标解析：找到双轨的根源

跟踪每次输入时光标的 DOM 落点：

```
空代码块结构：pre(#ag-95) > code(#ag-96, class=ag-paragraph) > codeContent span(#ag-97)
输入 a/b 后：光标在 code#ag-96 的直属文本节点
```

muya 的 `selection.getCursorRange()` 用 **最近的 `.ag-paragraph` 元素** 解析 block key（`findNearestParagraph`）。空代码块里光标落在带 `ag-paragraph` class 的 **`code` 元素**（`type='code'` 的外层 code block）上，因此 `inputHandler` 拿到的 block 是 **code block**（`functionType` 为 undefined），而不是内部的 **codeContent span**（`functionType='codeContent'`）。

渲染器（`renderLeafBlock.js`）渲染代码块时读取的是 **codeContent span** 的 text。两条路径各写各读，互不同步。

## 3. 根因

**muya 代码块的模型是两级结构，输入与渲染读写的是不同层级：**

```
pre block (type='pre', functionType='fencecode')
├── span (languageInput，语言标签 "js")
└── code block (type='code')           ← 输入写入这里（空代码块的光标落点）
    └── span (codeContent)             ← 渲染读取这里
```

分情况：
- **带语言代码块**：光标落在 codeContent span 的文本节点里，`getCursorRange` 解析为 codeContent span → 输入更新 span.text → 渲染读 span.text → **一致，正常**。
- **无语言代码块**：光标解析到外层 `code` block（`type='code'`，本身带 `ag-paragraph` class）→ 输入更新的是 **code block.text**；渲染仍读 **codeContent span.text**（从未被更新，为空）→ **不一致**。

为什么"平时看不出问题、一输入括号才出事"：

| 输入 | 是否触发渲染 | 结果 |
|---|---|---|
| 普通字符 `a`、`b` | 不触发（`needRender=false`，代码块分支防抖只服务 span） | 浏览器直插 DOM 直接显示，模型同步，**看似正常** |
| `(` `[` `{` 等 autoPair 字符 | **立即触发 `partialRender()`**（`needRender=true`） | 渲染读空的 codeContent span → **整个 pre 被重建为空白** → "内容被清空" |

也就是说：普通字符完全靠浏览器原生插入显示，掩盖了双轨不一致；括号的自动配对补全（`text` 修改 + `needRender=true`）触发同步重渲染，才让"渲染读空"暴露出来。

### 与其他已知问题的关系

`问题记录.md` 问题 5 记录的是另一条修复线（Mermaid 代码块 + 中文输入法 composition + MutationObserver 全量重渲）。两条线的症状相似（"输入 `(` 后内容消失"）但**根因完全不同**：

- 问题 5（已修）：IME 合成期间 observer 触发 `render(true)` 打断合成、清掉 DOM。
- 本问题：无输入法也能触发；是 code / codeContent 双轨模型不一致，渲染读空。

本修复后，即使没有任何 IME，空代码块输入 `(` 也不再生效清空。

## 4. 修复方案

### 4.1 核心修复（已实施）

`contentState/inputCtrl.js` 的 `inputHandler`：光标解析到 `type='code'` 的 code block 时，重定向到其 `codeContent` 子块，使输入更新与渲染读取指向同一对象：

```js
const key = start.key
let block = this.getBlock(key)
// Fix: 无语言代码块的 codeContent 光标会解析到外层 code block（type='code'），
// 而渲染读取的是其 codeContent 子块文本。重定向到 codeContent 保证模型与渲染一致，
// 否则 autoPair 等触发渲染的输入会把已输入内容渲染为空。
if (block && block.type === 'code' && block.children.length && block.children[0].functionType === 'codeContent') {
  block = block.children[0]
}
const paragraph = document.querySelector(`#${key}`)
```

重定向后：
- autoPair 补全写入 codeContent span 的 text；
- `codeContent` 分支（300ms 防抖 / `needRender` 立即渲染）正常命中；
- 渲染读取 codeContent span.text → 与模型一致。

### 4.2 对候选方案的评估（为什么没有采用外部方案）

排查前收到的 Gemini 方案（`inputCtrl.js:338-350` 改用 `singleRender`、`codeBlockUpdate` 禁止重置）经源码核对与实测，**均不对症**：

| 方案 | 评估 |
|---|---|
| 方案一：代码块内 `needRender` 时用 `singleRender(block)` 替代 `partialRender()` | 未命中根因。问题不在"渲染销毁 DOM"，而在"渲染读错了文本对象"；换成 singleRender 依然读空的 codeContent span，照样清空。且 `singleRender` 的参数应为 block（不是单行），Gemini 的"单块精确局部更新"描述与实际 API 语义不符 |
| 方案二：`codeBlockUpdate` 增加 `block.type !== 'p'` 直接 return | 该函数只在输入 ``` 转 pre 时触发，与"已存在代码块输入括号"无关。实测模型从未被清空（`code.text` 始终为 `ab()`），不存在"被重置为空"的路径 |

## 6. 经验教训

1. **症状相同的 bug 可能根因不同**：本问题与 `问题记录.md` 问题 5 症状几乎一样，但一个是 IME/observer 路径，一个是模型双轨；修复前必须用事件流 + DOM 追踪 + 模型读取代证明确认路径，避免把上一次的"修复结论"直接套用。
2. **"平时正常"可能只是掩盖**：普通字符不触发渲染，掩盖了模型双轨不一致；只有触发重渲染的路径才会暴露。排查时应主动寻找"什么操作会触发重渲染"。
3. **渲染读与输入写必须指向同一对象**：muya 代码块的 `code` block 与 `codeContent` span 是双份文本存储，任何编辑路径都应保持二者指向一致后再更新。
