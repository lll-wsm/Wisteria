# 代码块复制按钮显示双图标 —— 根因分析与修复方案

- 状态：已修复
- 日期：2026-08-31
- 涉及文件：`src/style.css`（+7 行覆盖规则），提交 `351706a`
- 现象环境：所有代码块（空 / 有内容 / 带语言 / 不带语言）右上角复制按钮显示**两个相同的复制图标**

## 1. 问题描述

代码块右上角的复制按钮区域出现**两个外观一致、挨在一起的复制图标**，鼠标移上去两个图标会一起变亮、移开一起变暗（同一个 hover 行为）。用户原话："显示的是两个复制按钮的图标，实际上鼠标移动到复制按钮上两个都有反应，应该是一个按钮显示两个图标；代码块是空的内容也是这样，和代码内容没有关系。"

| 观察维度 | 表现 |
|---|---|
| 空代码块 | 双图标 ✓ |
| 带语言代码块（```js 等） | 双图标 ✓ |
| 图标外观 | 两个图形相同 |
| hover 行为 | 两个图标同时响应（同亮同暗） |
| 点击 | 复制功能可用 |

## 2. 排查过程（证据链）

### 2.1 排除"两个 DOM 按钮"的可能

对真实应用做全场景 DOM 计数：初始加载、点击复制、输入字符、输入括号、方向键跨界、快速连打压力测试、切换文件、空代码块、Mermaid 块编辑——**所有场景下每个 `pre` 里都只有 1 个 `a.ag-code-copy` 元素**，从未出现第二个按钮节点。

结论：不是"两个按钮元素"，而是**一个按钮元素渲染出了两个图标图形**——这也解释了为什么 hover 时两个图标同时响应（它们是同一元素的不同绘制）。

### 2.2 用户截图分析

用户提供截图（1375×251）后，用纯 Python 编写的 PNG 解码器 + 二值化渲染 + macOS Vision OCR 分析：

- 截图为深色主题代码块局部，识别出多个小图形簇；
- 单个图形簇约 10-20px 见方，符合"图标"而非文字；
- OCR 无法识别图标，但可见并排的同类图形。

像素级证据与下述代码级证据互相印证——重点是代码机制，而不是单纯数像素。

### 2.3 代码级定位：雪碧图技巧的双重绘制

排查 muya 复制按钮的渲染结构（`muya-core/src/muya/lib/parser/render/renderBlock/renderCopyButton.js`）：

```js
const renderCopyButton = (t) => {
  const selector = 'a.ag-code-copy'
  const iconVnode = h('i.icon', h('i.icon-inner', {
    style: {
      background: `url(${copyIcon}) no-repeat`,
      'background-size': '100%'
    }
  }, ''))
  return h(selector, {...}, iconVnode)
}
```

DOM 结构：`a.ag-code-copy > i.icon > i.icon-inner`，其中 `i.icon-inner` 用**独立 PNG**（40×40，渲染为 16×16）作复制图标。

muya 通用 CSS（`muya-core/src/muya/lib/assets/styles/index.css`）有两处关键规则（这类 CSS 用 `i.icon > i[class^='icon-']` 选择器做**雪碧图偏移技巧**）：

```css
.ag-code-copy i.icon {
  position: absolute;
  top: 2px;
  left: 2px;
  width: 16px;
  height: 16px;
  /* 注意：没有 overflow: hidden，其他图标组件的 i.icon 都有 */
}

.ag-code-copy i.icon > i[class^='icon-'] {
  width: 100%;
  height: 100%;
  filter: drop-shadow(16px 0 var(--iconColor));
  position: absolute;
  left: -16px;
}
```

`i.icon-inner` 的 class 以 `icon-` 开头，**命中了第二条规则**：

- `left: -16px` —— 图标元素（含其 PNG 背景）被向左移 16px，原始 PNG 画在按钮左侧 14px 处（按钮内图标位置为 2,2..18,18，偏移后为 -14..+2）；
- `filter: drop-shadow(16px 0 var(--iconColor))` —— 把图标的**形状副本**沿 x 轴 +16px 投影回按钮原位，用 `--iconColor` 填充；
- 关键差异：`.ag-code-copy i.icon` **没有 `overflow:hidden`**（对比 `.ag-front-icon i.icon`、工具栏图标等都有），所以左移的原始 PNG **不会被裁剪** → 原始 PNG 与影子副本**同时可见** → 并排两个相同图标。

而其他图标组件（工具条、front icon 等）也用同一技巧但父容器有 `overflow:hidden`，左移的原始图被裁掉，只显示影子副本 → 正常单图标。

### 2.4 变量回归确认：为什么"这两天又出现"

影子副本是否生成完全取决于 `var(--iconColor)` 是否解析为有效颜色：

| `--iconColor` 状态 | drop-shadow 效果 | 可见图标 |
|---|---|---|
| **未定义**（无效属性值） | 整条 filter 无效，被浏览器丢弃 | 只有左移的原始 PNG（单图标，但位置偏左、hover 区错位） |
| **有定义** | 影子副本生成 | 原始 PNG + 影子 = **双图标** |

用 `git log -S 'iconColor:'` 追踪：`--iconColor` 是提交 `aa63cd5`（本轮"代码块相关修复与编辑器功能优化"，含主题/暗色模式工作）才在 `src/style.css:28,53` 引入：

```css
:root { --iconColor: rgba(44, 62, 80, 0.6); ... }        /* 亮色 */
body.theme-dark { --iconColor: rgba(224, 224, 224, 0.6); ... } /* 暗色 */
```

此前全仓库（含 muya）都没有定义该变量 → copy 按钮的 drop-shadow 一直无效 → 单图标；`aa63cd5` 定义变量后 → 影子副本被激活 → 双图标回归。**与"之前修过、这两天又出现"的时间线完全吻合。**

### 2.5 真实应用实测（修复前后对照）

探针在真实 Electron 应用中强制显示复制按钮，沿按钮中线做 `elementFromPoint` 采样：

```
修复前：
  x=768-782  → i.icon-inner（左移后的原始 PNG 盒子）
  x=784-798  → i.icon（按钮内图标位置，影子副本所在）
  计算样式：left:-16px；filter: drop-shadow(16px 0 rgba(44,62,80,.6))

修复后：
  x=784-798  → i.icon-inner（仅按钮内一处）
  计算样式：left:0px；filter: none
```

## 3. 根因

**单个复制按钮元素内部，muya 的雪碧图偏移技巧因 `--iconColor` 变量被定义而双重绘制**：

```
a.ag-code-copy (20×20，右上角)
└── i.icon (16×16，无 overflow:hidden)
    └── i.icon-inner (class 命中 i[class^='icon-'])
        ├── 原始 PNG：left:-16px → 画在按钮左侧 (-14..+2)
        └── drop-shadow(16px 0 var(--iconColor)) 影子 → 画在按钮内 (+2..+18)
```

两个图形形状相同、贴合在一起、属于同一元素 → 视觉上是"一个按钮两个图标"，hover 一起亮、点击一起可用。

触发条件链：

1. muya 把复制按钮图标故意做成 `i[class^='icon-']` class（本意是复用雪碧图技巧）；
2. `renderCopyButton` 用的却是独立 PNG（而非雪碧图），且 `i.icon` 无 `overflow:hidden`；
3. 雪碧图技巧在无裁剪时会把"原始图 + 影子"都画出来；
4. 影子是否出现由 `var(--iconColor)` 决定——本项目主题工作引入该变量后影子被激活。

## 4. 修复方案

### 4.1 核心修复（已实施，`src/style.css` +7 行）

复制按钮用独立 PNG，本就该一次性原位显示。对命中雪碧图规则的复制按钮图标，直接禁用偏移与影子：

```css
/* Copy button uses its own PNG icon; neutralize muya's sprite trick
   (left:-16px + drop-shadow) so the icon renders once, in place. */
#ag-editor-id a.ag-code-copy i.icon > i[class^='icon-'] {
  left: 0;
  filter: none;
}
```

- `left: 0` —— 取消 16px 左移，PNG 回到按钮内原位；
- `filter: none` —— 取消 drop-shadow，不生成影子副本；
- 选择器带 `#ag-editor-id`，优先级 (1,3,3) 高于 muya 原规则 (0,3,2)，稳定覆盖；
- 只作用于 `.ag-code-copy`，不影响其他图标组件（它们用 `currentColor` + `overflow:hidden` 的正确雪碧图技巧，正常单图标）。

### 4.2 不采用的替代方案

| 方案 | 评估 |
|---|---|
| 删除 `--iconColor` 变量定义 | 变量被本项目多个样式使用（表格拖拽手柄的边框/圆点、loading 动画边框等，`src/style.css:250-295`），删掉会使这些 UI 失效；且恢复"变量未定义"等于回到隐性依赖，后续任何人再定义变量双图标就会复发 |
| 改 muya 源码（给 `.ag-code-copy i.icon` 加 `overflow:hidden` 或改 class 名） | 也能修，但 vendor 目录改动范围大；且用户修复的是 UI 表现，CSS 层覆盖更小更安全 |
| 删除 `i.icon-inner` 的 `icon-` 前缀 class | 会改变渲染结构，复制按钮事件/样式依赖该结构，风险高 |

### 4.3 附带说明（排查中排除的其他候选）

- **标题"复制链接"图标**：muya 原生对 h1-h6 激活时显示 `ag-copy-header-link` 复制链接按钮（`renderIcon.js`），外观是链接图标，若文档中标题与代码块相邻容易被误认——真实存在，但不是本次双图标来源（图标外观不同、触发条件不同）。
- **Mermaid 块复制按钮定位漂移**：按钮 `right:0.5em` 锚定块内容宽度，Mermaid 图渲染后宽度塌缩，按钮会偏离视口右侧——观测到，但与"双图标"无关。

## 6. 经验教训

1. **"两个按钮"未必是两个 DOM 元素**：单元素通过 sprite 偏移 + drop-shadow 可绘制出两个相同图形。排查第一步先数 DOM 节点，但**不能以"DOM 只有一个元素"就下结论**——要验证"实际画了几个图形"（elementFromPoint + 计算样式 + 像素）。
2. **CSS 变量从"未定义"变为"有定义"会激活整条隐藏规则**：`filter: drop-shadow(... var(--iconColor))` 这类写法在变量缺失时整条规则静默失效。主题/变量重构会把之前"看似没生效"的路径激活，回归往往因此而来——排查回归时要对新增的 CSS 变量做全量引用审计。
3. **视觉问题最终落到渲染机制**：先读渲染结构（HTML 结构 + class 选择器命中关系）、验证计算样式，比在像素图上猜测高效得多；用户截图用于确认"看到了什么"，机制分析用于确认"为什么"。
